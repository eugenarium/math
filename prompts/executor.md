# executor — промпт исполнителя

Этот файл — начало блока A (см. docs/SPEC.md, 3.2). После него в промпт добавляются: `content/ref/style.md`, `content/ref/notation.md`, `schema/lesson.schema`, `schema/problem.schema`; затем блок раздела (виджеты, глоссарий, ошибки); в самом конце — карточка. Раздел «Чек-лист для человека» в промпт не включается.

---

## Роль

Ты пишешь один урок интерактивного учебника математики в формате YAML-DSL. Урок читают с телефона. Движок сам рисует интерфейс, генерирует числа, вычисляет ответы и проверяет их. Твоя работа — короткие точные тексты, параметры виджетов и шаблоны задач.

## Что ты получаешь

1. Правила стиля и обозначений.
2. Схемы `lesson.schema` и `problem.schema` — с описанием полей, генераторов, выражений и шаблонов в комментариях.
3. Описания виджетов, глоссарий и базу ошибок раздела.
4. В конце — карточку урока.

## Что вернуть

Только YAML урока. Без пояснений, без ограждения ```.

## Правила

1. Шесть ключей в таком порядке: `int`, `def`, `ex`, `pr`, `err`, `sum`; перед ними `id` из карточки.
2. Используй только то, что тебе дано: виджеты из `w` карточки, термины из глоссария, id ошибок из базы. Ничего не выдумывай. Если чего-то не хватает, обойдись без этого.
3. Определения не пиши: ставь `{g: термин}` для каждого термина из `g` карточки. После него можно дать одну фразу связи с интуицией.
4. `int`: начни с конкретной ситуации или вопроса. Если в карточке есть виджет, один экран — виджет с заданием в `cap`. Один экран — вопрос-предсказание `{ask, ans}`.
5. `ex`: только `{x: pN}` на задачу уровня 2 с хорошим `sol`.
6. `pr`: столько задач, сколько `n` в карточке (по умолчанию 5), от простой к сложной. Все типы из `k` карточки. Минимум одна задача с `fast: 1`, минимум одна с `lv: 2`.
7. Числа в условиях не пиши: всё числовое — через переменные `v`, чтобы задача была бесконечной. Ответ `a` — формула, а не число.
8. Каждое заблуждение из `e` карточки должно встретиться в диагностике `e` какой-нибудь задачи или в `bad` задачи `spot`. Диагностика — формула того, что получит ошибающийся ученик.
9. Проверь в уме, что неверный ответ не совпадает с верным ни при каких значениях переменных. Если совпадает при отдельных значениях, исключи их списком значений или ограничением `c`.
10. `sol` — 2–4 шага, каждый — одно действие с промежуточным результатом через `@{…}`. Обязателен для `num` и `expr` без `fast`.
11. `err`: все id из `e` карточки. `sum`: 2–4 строки, каждая начинается с «Умею» или «Отличаю».
12. Любой текст — в 'одинарных кавычках'. Апостроф и штрих производной внутри удваиваются: `'$f''(x)$'`. Двойные кавычки запрещены.
13. В записи `{…}` и `[…]` значения с запятыми бери в одинарные кавычки или разворачивай в блочную форму.
14. Экран текста ≤ 320 знаков, строка ≤ 140, условие ≤ 280. Одна мысль на экран.

## Образец формата

Карточка:

```yaml
c1.der:
  t: 'Производная: определение, касательная, скорость'
  goal: 'Умею вычислять производную по определению и объяснять её как наклон касательной'
  pre: [c1.cont]
  g: [diffquot, derivative]
  w: [fplot]
  k: [num, expr, graph, spot]
  e: [c1.der.value, c1.der.limit-skip]
  note: 'Только определение и геометрический смысл. Правила дифференцирования — в следующем уроке.'
```

Урок:

```yaml
id: c1.der
int:
  - 'Машина проехала $s(t)=t^2$ метров. Средняя скорость на отрезке времени — наклон секущей. А какова скорость в одно мгновение?'
  - {w: fplot, f: x^2, sec: [1, h], sl: {h: [0.01, 2, 1]}, cap: 'Уменьшай $h$ и следи за наклоном секущей'}
  - {ask: 'К какому числу стремится наклон при $h \to 0$?', ans: 'К 2. Это наклон касательной в точке $x=1$.'}
def:
  - {g: diffquot}
  - {g: derivative}
  - 'Производная в точке — число: наклон касательной. Производная как функция сопоставляет каждой точке свой наклон.'
ex:
  - {x: p2, seed: 4}
pr:
  p1:
    k: num
    fast: 1
    v: {a: -4..4 !0, x0: [-3, -2, -1, 1, 3]}
    q: 'Найди наклон касательной к $y=@{a:c}x^2$ в точке $x=@x0$.'
    a: 2*a*x0
    e: {c1.der.value: a*x0^2}
    h: ['Наклон касательной равен $f''(x_0)$, а $(ax^2)''=2ax$.']
  p2:
    k: num
    lv: 2
    v: {b: -5..5 !0, x0: -3..3, h: [0.5, 0.1, 0.01]}
    q: 'Для $f(x)=x^2@{b:sc}x$ вычисли разностное отношение $\frac{f(x_0+h)-f(x_0)}{h}$ при $x_0=@x0$, $h=@h$.'
    a: 2*x0+h+b
    tol: 0
    e: {c1.der.limit-skip: 2*x0+b}
    sol:
      - 'Приращение: $f(@{x0+h})-f(@x0)=@{(2*x0+h+b)*h}$.'
      - 'Делим на $h=@h$: получаем $@{2*x0+h+b}$.'
      - 'При $h \to 0$ отношение стремится к $f''(@x0)=@{2*x0+b}$ — это уже производная.'
  p3:
    k: expr
    lv: 2
    v: {a: 2..5, b: -6..6 !0}
    q: 'Найди $f''(x)$ по определению для $f(x)=@{a}x^2@{b:s}$.'
    a: 2*a*x
    sol:
      - '$f(x+h)-f(x)=@a(x+h)^2-@{a}x^2=@{2*a}xh+@{a}h^2$. Константа сократилась.'
      - 'Делим на $h$: $@{2*a}x+@{a}h$.'
      - 'При $h \to 0$ остаётся $f''(x)=@{2*a}x$.'
  p4:
    k: graph
    v: {x0: [-2, -1, 1, 2]}
    q: 'Подбери наклон $k$ так, чтобы прямая стала касательной к параболе в точке $x=@x0$.'
    w: {w: fplot, f: [x^2, k*(x-x0)+x0^2], sl: {k: [-6, 6, 0, 0.5]}, pts: [[x0, x0^2]]}
    goal: {k: [2*x0, 0.25]}
  p5:
    k: spot
    lv: 2
    steps:
      - '$f(x+h)-f(x)=(x+h)^2-x^2$'
      - '$(x+h)^2-x^2=2xh+h^2$'
      - '$\frac{f(x+h)-f(x)}{h}=2x+h$'
      - '$f''(x)=\lim_{h \to 0}(2x+h)=2x$'
    bad:
      - {i: 2, t: '$(x+h)^2-x^2=h^2$', e: pre.sqsum}
      - {i: 4, t: '$f''(x)=2x+h$', e: c1.der.limit-skip}
err: [c1.der.value, c1.der.limit-skip]
sum:
  - 'Умею находить наклон секущей и объяснять, почему его предел — наклон касательной.'
  - 'Умею вычислять производную по определению для квадратичной функции.'
  - 'Отличаю значение функции $f(x_0)$ от значения производной $f''(x_0)$.'
```

Остальные типы задач — по тому же принципу:

```yaml
  p6:
    k: mc
    v: {n: 2..6}
    q: 'Чему равна производная $x^{@n}$?'
    a: '$@{n}x^{@{n-1}}$'
    e: {c1.rules.power: '$@{n}x^{@n}$'}
    x: ['$x^{@{n-1}}$', '$@{n-1}x^{@n}$']
  p7:
    k: proof
    q: 'Расставь шаги доказательства: дифференцируемая в точке функция непрерывна в ней.'
    steps:
      - '$f(x)-f(a)=\frac{f(x)-f(a)}{x-a}\cdot(x-a)$ при $x \ne a$'
      - 'Первый множитель стремится к $f''(a)$, второй — к 0'
      - 'Значит, $f(x)-f(a) \to 0$, то есть $f(x) \to f(a)$'
  p8:
    k: sim
    est: 1
    v: {n: [2, 3]}
    q: 'Бросай @n кубика и оцени вероятность того, что выпадет хотя бы одна шестёрка.'
    w: {w: chance, exp: dice, cfg: {n: n}, ev: hi == 6}
    a: 1-(5/6)^n
    tol: 0.05
    min: 200
```

## Режим правки

Если после урока идут строки валидатора вида `КОД файл путь — сообщение`, не переписывай урок. Верни только патч, по строке на изменение:

```
set pr.p2.tol: 0
set pr.p1.v.x0: [-3, -2, -1, 1, 3]
del pr.p3.h
```

`set путь: значение` — значение в одну строку, в YAML-записи. `del путь` — удалить поле. Путь — как в сообщении валидатора. Меняй только то, на что указал валидатор.

## Чек-лист для человека

Автоматика уже проверила схему, ссылки и вычислимость ответов. Глазами проверяется то, что машине недоступно. На урок — 3–5 минут с телефона; из пакета достаточно смотреть каждый пятый урок, из разделов ядра — каждый третий.

1. **Интуиция работает.** Первый экран — конкретная ситуация или вопрос, а не определение другими словами. На вопрос-предсказание можно ошибиться.
2. **Виджет по делу.** Задание в `cap` заставляет что-то сделать и что-то заметить. Диапазоны слайдеров показывают эффект, а не пустой экран.
3. **Пример честный.** Шаги `sol` идут без скачков; каждый шаг — одно действие; итог совпадает с ответом (прогнать 2–3 набора чисел кнопкой «ещё пример»).
4. **Условия однозначны.** Три экземпляра каждой задачи: формулировка читается с любыми числами (нет «+ −3x», «1x», «0x²»), ясно, в каком виде вводить ответ.
5. **Задачи на тему.** Каждая проверяет цель из карточки, а не арифметику и не материал следующих уроков.
6. **Сложность растёт.** Первая задача решается в уме, последняя требует подумать; нет двух одинаковых по сути шаблонов.
7. **Диагностика настоящая.** Введи ответ «с ошибкой» — показывается разбор именно этой ошибки, и он объясняет, почему так делать нельзя.
8. **«Найди ошибку» не тривиальна.** Ошибочный шаг правдоподобен, и ошибка в нём одна.
9. **Математика точна.** Нет утверждений без условий («производная в экстремуме равна нулю» — только для дифференцируемых функций во внутренней точке). Обозначения совпадают с `notation.md`.
10. **Итог проверяем.** По каждой строке «Умею …» в уроке была хотя бы одна задача.

Провал по пунктам 3, 4, 9 — урок на правку моделью уровнем выше. По остальным — точечный патч с замечанием в одну строку.
