# PLAN — порядок работ

## Уровни моделей

| Уровень | Что делает | Почему |
|---|---|---|
| **Сильная** (старшая модель в агентном режиме с доступом к репозиторию) | Ядро движка: `gen.js`, `check.js`, `plot.js`, плеер урока, `tools/check.mjs`. Сложные виджеты: `matrix`, `graph`, `contour`, `sample`, все 3D. Уроки, не прошедшие два круга правки у средней | Ошибка в ядре размножается на все уроки. Объём разовый |
| **Средняя** | Карточки по карте курса. Глоссарий и база ошибок по разделам. Простые виджеты по контракту `meta` + `mount`. Уроки разделов с доказательствами и тонкими формулировками: lg, c1.seq–c1.small, st.est, st.ci, st.test, все уроки с задачами `proof`. Проверяющая модель в `audit` | Определения и заблуждения — источник точности всего курса: их мало, а ссылаются на них все |
| **Дешёвая** | Массовые уроки по карточкам. Патчи по сообщениям валидатора. Наборы пар для игры | Задача сведена к заполнению формы по образцу, результат проверяет машина |
| **Без модели** | Проверка, сборка, применение патчей, сверка `audit`, публикация | |
| **Ты** | Выбор следующего раздела, просмотр карточек и справочников раздела (10–15 минут), чек-лист по выборке уроков с телефона | |

Правило эскалации: урок не прошёл `check` после двух патчей дешёвой модели → средняя; не прошёл у средней или провалил пункты 3, 4, 9 чек-листа → сильная или ручная правка карточки (чаще всего виновата карточка).

## Этап 0. Минимум за один вечер (3.5–4 часа)

Цель вечера: на телефоне открывается офлайн-приложение с тремя настоящими уроками, прогресс сохраняется, уроки сгенерированы дешёвой моделью и прошли проверку. Этим проверяется вся цепочка, а не красота.

| Время | Шаг | Кто | Готово, когда |
|---|---|---|---|
| 0:00–0:20 | Репозиторий, Vite + Preact, зависимости, файлы из этого набора на местах, публикация на GitHub Pages | сильная | пустая страница открывается с телефона |
| 0:20–1:30 | `gen.js` (генераторы, шаблоны, форматы), `check.js` для `num` и `mc`, `build.mjs`, плеер урока: шесть фаз, KaTeX, цифровая клавиатура, подсказки, решение | сильная | образец урока из `prompts/executor.md` (без p3–p5) проходится от начала до конца |
| 1:30–2:00 | `plot.js` и виджет `fplot`: кривые, слайдеры, секущая, касательная | сильная | экран интуиции образца работает пальцем |
| 2:00–2:30 | `check.mjs`: схема, E101–E103, E105, E201, E205, прогон генераторов E301–E305 | сильная | намеренно испорченный образец даёт однострочные ошибки |
| 2:30–3:10 | Вручную: 3 карточки (pre.graph, c1.der, c1.rules), 15 терминов глоссария, 6 записей ошибок. `pack.mjs` в простейшем виде. Генерация трёх уроков, патчи | ты + дешёвая | три урока проходят `check` |
| 3:10–3:40 | `store.js` (прогресс и место остановки), манифест, сервис-воркер, публикация | сильная | приложение на домашнем экране, работает в режиме полёта, прогресс переживает перезапуск |
| 3:40–4:00 | Пройти три урока с телефона по чек-листу, записать замечания к DSL и промпту | ты | список правок к блоку A |

В минимум сознательно не входят: типы `expr`, `graph`, `spot`, `proof`, `sim`; повторения; карта курса; все виджеты, кроме `fplot`; игровой слой.

## Этап 1. Полное ядро движка (2–3 вечера)

1. Остальные типы задач: `expr` с экранной клавиатурой, `graph`, `spot`, `proof`, `sim`.
2. `mastery.js`: критерий усвоения, адаптивный порядок, экзамен экстерном.
3. `srs.js`: интервалы, сессия дня, перемешивание.
4. Карта курса: открытые, пройденные, закрытые уроки; выбор следующего.
5. `check.mjs` целиком: все коды E и W.
6. `gen.mjs`, `patch.mjs`, `audit.mjs`.
7. Экспорт и импорт прогресса.
8. Тесты `node --test` для `core`.

Результат: движок, в который можно лить контент. **После этапа блок A замораживается** — по замечаниям из вечера 0 в него вносятся последние правки.

## Этап 2. Виджеты P0 и справочники ядра (3–4 вечера)

1. Виджеты P0 в порядке первой потребности: `limit`, `taylor`, `riemann` → `vec2`, `lin2`, `matrix` → `truth`, `graph` → `chance`, `bayes`, `dist`, `sample`, `scatter` → `contour`. Сильная пишет сложные, средняя — остальные; каждый проверяется на странице `/#/lab`.
2. `course.yml` и карточки всех уроков ядра — средняя модель по `COURSE_MAP.md`, по разделу за запрос. Ты просматриваешь цели и заблуждения.
3. Глоссарий и база ошибок для разделов pre, lg, c1, la — средняя модель; вход: карточки раздела и `notation.md`. Просмотр глазами обязателен: это единственное место, где живут определения.

## Этап 3. Массовая генерация ядра (по разделу за вечер)

Порядок разделов: **pre → lg → c1 → la → dm → gr → pr → st → sr → cm → op → de → nm**. Первые четыре дают две параллельные линии обучения; учиться можно начинать после pre и первых уроков c1.

Цикл на раздел:
1. Справочники раздела готовы и просмотрены (для pr, st и далее — сделать перед разделом).
2. `npm run pack <раздел>`; `npm run gen <раздел>` — первый запрос один, остальные параллельно.
3. `check` → патчи → эскалация упавших.
4. `npm run audit <раздел>`; расхождения разобрать.
5. С телефона: каждый третий урок по чек-листу. Системные замечания (повторяются в трёх уроках и более) исправляются в справочниках или карточках раздела, а не в блоке A.
6. Публикация.

Виджеты P1 делаются перед разделом, которому нужны: `numline` (pre), `series` (sr), `venn`, `ctree` (dm, pr), `ci`, `test` (st), `slope`, `phase` (de), `iter`, `interp` (nm), `lp` (op).

## Этап 4. Игровой слой (после работающего ядра с контентом, 2–3 вечера)

Начинать, когда пройдены твои первые 15–20 уроков: к этому моменту видно, чего не хватает в ядре, и есть задачи для игр.

1. XP, уровни, серии — подписка на события ядра, полвечера.
2. Боссы разделов.
3. Мини-игры в порядке отдачи: «Спринт» → «Сыщик» → «Мишень» → «Глазомер» → «Сборка» → «Пары».
4. `pairs.yml` — дешёвая модель, по набору на раздел.

## Этап 5. 3D (1–2 вечера)

`surf3` → `vec3` → `lin3` → `vol3`, каждый с запасным 2D-вариантом. Уроки cm и la, где карточка разрешает 3D, получают экран с 3D точечным патчем: `set int[1]: {w: surf3, …}`.

## Этап 6. Расширение и опции

Виджеты P2, затем разделы в порядке личной потребности. Рекомендуемый порядок расширения: st → pr → ml → op → la → nm → de → cm → dm → gr → lg → sr. Опциональные темы — только по запросу.

## Риски и ответы

| Риск | Ответ |
|---|---|
| Дешёвая модель пишет неверную формулу ответа | `audit` на каждом разделе ядра; диагностика E304 и W508 |
| Уроки одного раздела однообразны | Поле `note` карточки задаёт акцент; чек-лист, пункт 6 |
| DSL не выражает нужную задачу | Не расширять DSL под один урок. Три похожих случая — новый параметр виджета или функция в `mathx.js` |
| Изменение блока A сбрасывает кэш и расходится с готовыми уроками | Заморозка после этапа 1. Дальше — только совместимые добавления, готовые уроки проверяет `check` |
| Виджетов слишком много для одного человека | Строгий порядок P0 → P1 → P2 → 3D; урок без готового виджета обходится `fplot` и вопросом-предсказанием, виджет добавляется патчем позже |
| Потеря прогресса на телефоне | Установка на домашний экран, `storage.persist()`, напоминание об экспорте |
