# ARCHITECTURE — репозиторий, сборка, данные, проверки

## 1. Стек и обоснование

| Решение | Почему |
|---|---|
| Статический сайт, Vite + Preact, обычный JS с `// @ts-check` | Сборка всё равно нужна (YAML → JSON, проверки). Preact — 4 КБ, компонентов немного. Без TypeScript: меньше конфигурации для одного человека |
| Контент в YAML | На 20–30 % короче JSON, а обратная косая черта LaTeX не требует удвоения |
| KaTeX | Требование; рендер на устройстве, потому что формулы параметрические |
| math.js | Один разбор выражений для ответов, графиков и проверки; матрицы и символьная производная в комплекте |
| jStat | Проверенные функции распределений и квантили; писать свои — риск для точности |
| Свой модуль `plot.js` на Canvas 2D | Все 2D-виджеты строятся на одной базе (оси, кривые, перетаскивание). Графические библиотеки тяжелее и плохо умеют перетаскиваемые математические объекты |
| Three.js, ленивая загрузка | Только для четырёх 3D-виджетов. Plotly отклонён: несколько мегабайт |
| Без CAS | Выражения сравниваются численно в случайных точках — надёжнее и на порядки легче символьного сравнения |
| Своя экранная клавиатура | Готовые редакторы формул тяжёлые; нужно два десятка кнопок |
| localStorage, один ключ | Прогресс — десятки килобайт. Плюс экспорт и импорт файлом |
| vite-plugin-pwa | Сервис-воркер и манифест без ручного кода |
| GitHub Pages + Actions | Бесплатно; публикация по push, только если проверки прошли |

Зависимости времени выполнения: preact, katex, mathjs, jstat, three. Сборки: vite, vite-plugin-pwa, js-yaml, ajv. Больше ничего.

## 2. Структура репозитория

```
content/
  course.yml              порядок разделов, названия, маршруты, параметры боссов
  cards/<раздел>.yml      карточки уроков раздела: {id: карточка}
  lessons/<раздел>/<id>.yml
  ref/
    glossary.yml          {id: {t: термин, d: определение, s: одной фразой, sym: обозначение, sec: раздел}}
    errors.yml            {id: {t: название, bad: как ошибаются, why: почему неверно, fix: как правильно}}
    pairs.yml             наборы пар для игры «Пары»
    notation.md           единые обозначения
    style.md              стиль объяснений
schema/
  lesson.schema           урок и карточка
  problem.schema          задача
engine/
  core/
    gen.js                генераторы переменных, шаблоны @…, форматы
    mathx.js              библиотека функций выражений (над math.js и jStat)
    check.js              проверка ответов всех типов задач
    mastery.js            критерий усвоения, выбор следующей задачи
    srs.js                интервалы повторения, сессия дня
    store.js              прогресс: чтение, запись, миграции, экспорт
    plot.js               база 2D-графики
    md.js                 мини-разметка: **жирный**, $формула$, перенос строки
  ui/                     плеер урока, экраны фаз, виды задач по типам k, клавиатуры, карта курса
  widgets/<имя>.js        по модулю на виджет
  widgets3d/<имя>.js      3D, отдельный чанк
  meta/                   XP, серии, уровни, боссы (надстройка)
  games/<имя>.js          мини-игры (надстройка)
tools/
  check.mjs               валидатор + линтер + прогон генераторов
  build.mjs               YAML → dist/data/*.json
  pack.mjs                сборка блоков A и B промпта
  gen.mjs                 пакетная генерация уроков раздела
  patch.mjs               применение патча правки
  audit.mjs               выгрузка экземпляров задач для независимой проверки
  docs.mjs                таблицы параметров в WIDGETS.md из meta виджетов
prompts/executor.md
docs/
public/                   манифест, иконки
```

Правило зависимостей: `engine/core` не знает о `ui`, `meta` и `games`; `meta` и `games` только читают события ядра. Игровой слой можно удалить, не трогая ядро.

## 3. Команды

| Команда | Что делает |
|---|---|
| `npm run check [id\|раздел]` | Схема, ссылки, прогон генераторов (`tools/check.mjs`). Код возврата ≠ 0 при любой ошибке E. Полный `npm run check` дополнительно запускает тесты и проверки карты курса |
| `npm run build` | `check` → компиляция контента → `vite build` → сервис-воркер |
| `npm run dev` | Локальный сервер; при сохранении YAML — перепроверка и перезагрузка |
| `npm run pack <раздел>` | Пишет `out/pack/A.txt` и `out/pack/<раздел>.B.txt` |
| `npm run gen <раздел> [--only id,…]` | Для каждой карточки без урока: запрос к модели, запись файла, `check`, до двух кругов правки |
| `npm run patch <id> <файл>` | Применяет патч `set`/`del` и запускает `check <id>` |
| `npm run audit <id\|раздел>` | Печатает по 3 экземпляра каждой задачи и принимает решения проверяющей модели |
| `npm run docs` | Обновляет таблицы параметров в `docs/WIDGETS.md` |

## 4. Сборка контента

1. `content/**/*.yml` → разбор → проверка → `dist/data/index.json` (граф курса: id, заголовок, предпосылки, приоритет, время) и `dist/data/<раздел>.json` (уроки раздела), `dist/data/ref.json` (глоссарий и ошибки).
2. В уроке раскрываются умолчания, задачи получают глобальные id вида `c1.der#p2`.
3. Данные раздела подгружаются при первом входе в раздел; сервис-воркер кладёт в кэш оболочку, все данные и чанк Three.js, поэтому после первого запуска с сетью приложение полностью офлайновое.

## 5. Виджеты: контракт

```js
// engine/widgets/<имя>.js
export const meta = {
  name: 'fplot',
  params: { f: ['E|E[]', null, 'кривые'], x: ['range', [-5, 5], 'окно по x'] /* … */ },
  out: ['P.x', 'P.y'],            // слайдеры добавляются автоматически
};
export function mount(el, params, ctx) {
  // ctx: { plot, evalExpr, scope, rng, theme, onChange }
  return { get() {/* состояние по out */}, set(state) {}, destroy() {} };
}
```

- Реестр собирается на этапе сборки из `meta` всех модулей; линтер проверяет по нему имена и параметры.
- Модуль виджета подгружается динамическим `import()` по имени при первом показе.
- Параметры-выражения вычисляются в области видимости `ctx.scope`: слайдеры виджета плюс переменные задачи.
- Виджет не знает об уроках, прогрессе и проверке ответа. Цель `goal` проверяет `check.js` по `get()`.

Добавление виджета: один файл в `engine/widgets/` и `npm run docs`. Уроки и схемы не меняются.

## 6. Хранение прогресса

Один ключ `localStorage['mx']`, JSON:

```
{
  v: 1,                                   версия формата, миграции в store.js
  L: { 'c1.der': [st, box, due, n] },     st: 0 начат · 1 пройден · 2 «вернуться»; box — номер интервала;
                                          due — день следующего повторения (число дней от 2025-01-01, местное время);
                                          n — сколько раз повторён
  T: { 'c1.der#p2': [ok, bad] },          счётчики по шаблонам задач
  E: { 'c1.der.value': 3 },               сколько раз диагностировано заблуждение
  cur: { id, phase, i, last5 },           место остановки в текущем уроке
  xp: 0, days: [dLast, streak, freeze],   надстройка
  games: { sprint: { 'c1': 17 } },        рекорды
  set: { theme, haptics }
}
```

- Запись — после каждого ответа, целиком.
- `navigator.storage.persist()` при первом запуске. В настройках — экспорт и импорт файла `.json`; напоминание об экспорте раз в 30 дней. Приложение нужно добавить на домашний экран: так хранилище меньше рискует быть очищенным системой.
- Если урок удалён или переименован, его записи игнорируются; переименования перечисляются в `content/course.yml` (`renames`), и `store.js` переносит прогресс.

### Повторения

`srs.js` — чистые функции над `L`: `due(today)` — список уроков к повторению; `grade(id, right, of)` — новый `box` и `due` по правилам SPEC 2.5; `session(today)` — задачи дня вперемешку. Выбор шаблонов учитывает `T` и `E`: чаще выпадают шаблоны с ошибками и задачи, диагностирующие личные заблуждения.

## 7. Проверка ответов

| Тип | Алгоритм |
|---|---|
| `num` | Разбор ввода: десятичная точка или запятая, дробь `3/4`, для векторов и матриц — сетка полей. Сравнение поэлементно: \|x−a\| ≤ tol·max(1, \|a\|); при `tol: 0` допуск 1e-9 |
| `mc` | Сравнение индексов выбранных вариантов |
| `expr` | Разбор math.js; неизвестные идентификаторы — ошибка ввода, а не неверный ответ. 8 случайных точек из `dom`, точки с нечисловым значением заменяются; относительная погрешность 1e-6. При `const: 1` сравниваются разности значений между точками |
| `graph` | Для каждой переменной из `goal`: \|состояние − цель\| ≤ допуск |
| `spot` | Номер выбранной строки равен номеру подменённого шага |
| `proof` | `ord`: порядок совпадает с точностью до перестановок внутри `grp`. `why`: каждому шагу выбрано его обоснование |
| `sim` | Счётчик опытов виджета ≥ `min`, затем как `num` или `graph` |

Числа в шаблонах по умолчанию выводятся с 6 значащими цифрами без хвостовых нулей, минус — типографский.

## 8. Валидатор и линтер

`tools/check.mjs` использует те же `gen.js`, `mathx.js`, `check.js`, что и приложение: расхождений между проверкой и рантаймом быть не может.

Формат сообщения — одна строка: `КОД файл путь — сообщение`.

```
E303 content/lessons/c1/c1.der.yml pr.p2.a — NaN при seed=17 (h=0)
E204 content/lessons/c1/c1.der.yml err[1] — нет в errors.yml: c1.der.valu (возможно: c1.der.value)
```

| Код | Проверка |
|---|---|
| E101 | YAML не разобран (строка и причина) |
| E102 | Нарушена схема (путь, что ожидалось) |
| E103 | `id` не совпадает с именем файла или нет карточки |
| E105 | Строка в двойных кавычках содержит `\` |
| E201 | Предпосылка указывает на несуществующий урок |
| E202 | Цикл в предпосылках |
| E203 | Термин `{g: …}` или `g` карточки отсутствует в глоссарии |
| E204 | Id заблуждения отсутствует в `errors.yml` |
| E205 | `{x: pN}` или `from` указывает на несуществующую задачу; у задачи примера нет `sol` |
| E206 | Урок ядра зависит от урока расширения или опции |
| E207 | Не выполнено требование карточки: нет задачи обязательного типа `k`, не использован виджет `w`, в `err` нет заблуждения из `e` |
| E301 | В шаблоне или выражении использована неопределённая переменная |
| E302 | Ограничения `c` отбрасывают больше 80 % наборов |
| E303 | Ответ не вычислился: NaN, бесконечность, не тот тип (указан seed и значения) |
| E304 | Неверный вариант `mc` совпал с верным или с другим вариантом; диагностический ответ `e` попал в допуск верного более чем в 30 % наборов |
| E305 | KaTeX не отрисовал формулу после подстановки |
| E306 | Поле не относится к типу задачи `k` |
| E307 | У задачи нет способа проверки |
| E308 | `expr`: ответ не вычисляется на `dom` или содержит переменную не из `vars` |
| E309 | Нет `sol` у задачи `num` или `expr` без `fast` |
| E310 | `goal`: переменной нет в `out` виджета или цель вне диапазона слайдера |
| E401 | Виджета нет в реестре |
| E402 | Неизвестный параметр виджета или неверный тип значения |
| E403 | Виджет не разрешён карточкой |
| E404 | Выражение в параметре виджета не вычисляется |
| W502 | Формула, вероятно, шире экрана |
| W503 | Урок длиннее 6000 знаков (порог поднят с 3500 по результатам эталонных уроков, docs/SAMPLES.md) |
| W504 | Термин глоссария использован в тексте, но не введён ни этим уроком, ни предпосылками (пока не реализовано) |
| W505 | Нет ни одной задачи `fast` |
| W506 | Нет задачи уровня 2 или выше |
| W507 | Слова из стоп-списка стиля |
| W508 | Диагностика `e` совпала с верным ответом в части наборов (до 30 %): в этих наборах заблуждение не распознаётся |

Прогон генераторов: для каждой задачи 200 наборов с seed 1…200. Проверяется всё из группы E3xx; для `graph` и `sim` виджет не создаётся, проверяется только достижимость `goal` и вычислимость параметров.

Ошибки E блокируют сборку. Предупреждения W печатаются и не блокируют.

## 9. Конвейер генерации

```
карта → карточки → [pack] → исполнитель → check → патч (≤ 2 круга) → audit → выборочный просмотр человеком
```

- `gen.mjs` отправляет блоки A и B с пометками кэша, затем карточку. Ответ — чистый YAML, сохраняется как есть.
- При ошибках: модели уходит текущий файл и строки `check`, в ответ — патч `set`/`del` (формат в `prompts/executor.md`). Патч применяет `patch.mjs`.
- После двух неудачных кругов урок помечается в `out/failed.txt` и передаётся модели уровнем выше.
- `audit` обязателен для разделов ядра: расхождение между вычисленным ответом и решением проверяющей модели разбирает человек.

## 10. Игровая надстройка

Реализуется после рабочего ядра. Нового контента в уроках не требует: все величины вычисляются из событий ядра (`answer`, `lessonPassed`, `reviewDone`).

| Элемент | Правило |
|---|---|
| XP | Верно с первой попытки +10 · со второй или с подсказкой +5 · задача повторения +5 · урок пройден +50 · босс ×2 |
| Уровень | `1 + floor(sqrt(xp / 100))` |
| Серия | День засчитан, если завершено повторение дня или пройден урок. Заморозка: одна за каждые 7 дней серии, не больше двух в запасе |
| Босс раздела | 10 задач уровня 2–3 из разных уроков раздела, 3 жизни, без подсказок. Победа: значок раздела и +1 интервал всем урокам раздела. Поражение: уроки с ошибками назначаются на повторение завтра |
| Мини-игры | Шесть шаблонов из `docs/WIDGETS.md`; берут задачи по типу `k` и флагам `fast`, `est` |

## 11. Тесты

`node --test`: `gen.js` (детерминированность по seed, форматы), `check.js` (по 5–10 случаев на тип, включая эквивалентные формы выражений), `srs.js`, `mastery.js`, `store.js` (миграции). Виджеты проверяются вручную на странице `/#/lab`, где любой виджет открывается с параметрами из адресной строки.
