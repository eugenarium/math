# SPEC — цель, педагогическая модель, экономия токенов

## 1. Цель

Интерактивный учебник вузовской математики и статистики для одного человека, который проходит его с телефона короткими сессиями по 10–25 минут. Каждая тема — это действие: покрутить, предсказать, посчитать, найти ошибку. Чтения — минимум.

Продукт — статическое PWA: работает офлайн, прогресс хранится на устройстве, сервера нет.

Контент массово пишут дешёвые модели. Поэтому всё сложное и повторяющееся вынесено в движок и справочники, а урок — короткая декларативная запись, которую проверяет машина.

**Не цели:** замена учебника с полными доказательствами, совместная работа, аккаунты, синхронизация, собственный редактор уроков.

## 2. Педагогическая модель

### 2.1. Структура урока

Шесть фаз в фиксированном порядке; порядок закреплён схемой.

| Фаза | Ключ | Что происходит | Объём |
|---|---|---|---|
| Интуиция | `int` | Конкретная ситуация, виджет и вопрос-предсказание. Ученик сначала отвечает сам, потом видит результат | 1–3 экрана |
| Определение | `def` | Точная формулировка из глоссария и одна фраза связи с интуицией | 1–4 экрана |
| Разобранный пример | `ex` | Пошаговое решение, шаги открываются по одному. Строится из `sol` задачи | 1–2 экрана |
| Практика | `pr` | Параметрические задачи от простых к сложным, пока не выполнен критерий усвоения | 4–8 шаблонов |
| Типичные ошибки | `err` | Карточки заблуждений из базы: «как ошибаются → почему неверно → как правильно». Первыми идут ошибки, которые ученик сам допустил в практике | 1–3 карточки |
| Итог | `sum` | Строки «умею …» | 2–4 строки |

Почему так: предсказание до объяснения и самостоятельное извлечение ответа дают более прочное запоминание, чем чтение; ошибки показываются после практики, когда ученику есть с чем их сопоставить.

### 2.2. Экран

- Один экран — одна мысль. Текст ≤ 320 знаков, не больше одной выключной формулы.
- Горизонтальной прокрутки нет. Формула шире экрана масштабируется до 70 %, дальше линтер требует разбить её (W502).
- Кнопки «далее» и «проверить» — внизу, в зоне большого пальца; область касания не меньше 48 px.
- Ввод: числа — цифровая клавиатура с дробью и минусом; выражения — своя экранная клавиатура по разделу (x, ^, √, sin, ln, π, скобки) с живым предпросмотром в KaTeX.

### 2.3. Практика и обратная связь

- Задача выдаётся со случайными числами. Первая попытка: верно или неверно.
- Неверно: если ответ совпал с диагностикой `e`, показывается разбор именно этого заблуждения; иначе первая подсказка `h`. После второй неверной попытки открывается решение `sol`, и та же задача возвращается позже с другими числами.
- Порядок: уровень 1 → 2 → 3, шаблоны чередуются. Две ошибки подряд — возврат на уровень ниже.

### 2.4. Критерий усвоения

Урок **пройден**, когда одновременно:
1. из последних 5 задач не меньше 4 решены верно с первой попытки и без подсказок;
2. каждый шаблон уровня 2 и выше решён верно хотя бы раз.

Обычно это 6–10 задач. Если критерий не достигнут за 15 задач, урок получает статус «вернуться завтра», а ученику показывается ещё один разобранный пример.

**Экзамен экстерном:** кнопка «я это знаю» даёт 4 задачи максимального уровня без подсказок. Все верно — урок пройден и сразу попадает в повторение с интервалом 7 дней.

### 2.5. Повторение с интервалами

- Единица повторения — урок, а не карточка: задачи параметрические, каждый раз новые числа, заучить ответ нельзя.
- Интервалы в днях: **1 → 3 → 7 → 16 → 35 → 80 → 180**.
- Повторение урока — 3 задачи из разных шаблонов; в приоритете уровень 2+ и шаблоны, где у ученика были ошибки.
- 3 из 3 — следующий интервал · 2 из 3 — тот же · 0–1 из 3 — на два шага назад и предложение пересмотреть пример.
- Задачи разных уроков в сессии перемешиваются.
- Сессия дня: сначала повторения (до 10 уроков, около 15 минут), затем новый урок.

### 2.6. Открытие следующей темы

- Урок открыт, когда пройдены все его предпосылки (`pre` в карточке).
- Просроченные повторения новые уроки не блокируют; при долге больше 20 уроков показывается предупреждение.
- Доступно может быть несколько уроков из разных разделов; движок предлагает урок с наивысшим приоритетом по рекомендованному маршруту, выбор остаётся за учеником.
- Босс раздела открывается после прохождения всех уроков ядра этого раздела.

### 2.7. Точность

- Ответы задач вычисляет движок, а не модель: арифметические ошибки исключены.
- Определения живут только в глоссарии, заблуждения — только в базе ошибок. Их пишет модель среднего уровня один раз, человек просматривает по разделу.
- Каждая тема с меткой ⚠ в карте обязана иметь запись в базе ошибок и задачу с диагностикой `e` или типа `spot`.
- Независимая проверка: `npm run audit` выводит по 3 экземпляра каждой задачи текстом, другая модель решает их вслепую, скрипт сверяет с вычисленными ответами. Расхождение означает ошибку в условии или в формуле ответа.

## 3. Принципы экономии токенов

| № | Принцип | Как реализован |
|---|---|---|
| 1 | Урок — данные, не код | YAML-DSL с короткими ключами и значениями по умолчанию. Заголовок, цель и предпосылки в уроке не повторяются — они в карточке. Ориентир: урок ≤ 900 токенов; предупреждение при > 6000 знаков (W503) |
| 2 | Виджеты по имени | 34 виджета в `docs/WIDGETS.md`. Подключение — одна строка, 15–40 токенов |
| 3 | Параметрические задачи | Шаблон, генераторы и формула ответа, ≈ 60–120 токенов на задачу. Неверные варианты `mc` берутся из диагностики `e` |
| 4 | Справочники вместо повторов | `glossary.yml` — определения по ссылке `{g: id}` · `errors.yml` — фаза `err` состоит из одних id · `notation.md`, `style.md` входят в кэшируемую часть промпта |
| 5 | Карточка урока | ≈ 100 токенов. Исполнитель получает только её, схемы и срезы справочников; карту курса и другие уроки не получает |
| 6 | Машинная проверка | Схема, линтер, прогон генераторов. Каждая ошибка — одна строка с кодом и путём |
| 7 | Порядок генерации | Пакеты по разделам, неизменная часть промпта в начале — под кэш |
| 8 | Точечные правки | Исполнитель возвращает патч по путям из сообщений валидатора, а не новый урок |

### 3.1. Что в движке, что в описаниях

Правило: если что-то повторяется больше чем в трёх уроках или требует кода, оно уходит в движок или справочник.

| В движке | В справочниках | В уроке |
|---|---|---|
| Порядок фаз, навигация, оформление | Определения | Экраны интуиции: 2–3 абзаца и параметры виджета |
| Проверка ответов всех типов | Заблуждения и их разбор | Шаблоны задач: условие, генераторы, формула ответа, шаги решения |
| Генерация чисел, форматирование, перемешивание вариантов | Обозначения | Строки итога |
| Шаги матричных и графовых алгоритмов | Стиль | Ссылки: `{g: …}`, `{x: …}`, id ошибок |
| Подсказка «посмотри пример», критерий усвоения, повторения, XP, боссы, игры | Пары для игры | |

### 3.2. Сборка промпта

Порядок блоков — от самого стабильного к самому изменчивому. Границы кэша ставятся после A и после B.

```
A. Общий, один на весь курс:
   prompts/executor.md → content/ref/style.md → content/ref/notation.md
   → schema/lesson.schema → schema/problem.schema
   ─────────────── граница кэша 1
B. Раздела, один на пакет:
   описания виджетов, встречающихся в карточках раздела
   → срез глоссария: термины раздела полностью, термины предпосылок — только имя и обозначение
   → срез базы ошибок раздела
   ─────────────── граница кэша 2
C. Запроса, в самом конце:
   карточка урока
   (режим правки: текущий YAML урока + строки валидатора)
```

Блоки A и B собирает `npm run pack <раздел>`, побайтно одинаково при каждом запуске: порядок ключей и терминов фиксирован, дат и счётчиков в тексте нет. Любое изменение в A сбрасывает кэш всего курса, поэтому A замораживается до массовой генерации.

Пакет — один раздел. Первый запрос идёт один и прогревает кэш, остальные — параллельно в пределах времени жизни кэша. Если провайдер даёт скидку за пакетный режим, она складывается с кэшем.

### 3.3. Бюджет

| Что | Токены (ориентир) |
|---|---|
| Блок A | ≈ 10 тыс. (28 тыс. знаков), оплачивается полностью один раз на пакет, далее по цене чтения из кэша |
| Блок B | 2–4 тыс. на раздел |
| Карточка | ≈ 100 |
| Урок на выходе | 600–900 |
| Правка | вход: урок и 1–5 строк ошибок; выход: 20–100 |

На весь курс (208 уроков): около 180 тыс. токенов на выходе и около 2.5 млн на входе, почти все — из кэша. Основная статья расходов — выход, поэтому главный рычаг — краткость DSL.
